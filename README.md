# Hookahton

Личный список задач с регистрацией по email. У каждой задачи есть название, описание, время создания и отметка о выполнении.

## Запуск

Нужен Docker с Compose. Из корня репозитория:

```sh
docker compose up --build
```

Откройте http://localhost:8080. Порт можно задать в `.env`. Compose применяет миграцию при запуске и хранит данные PostgreSQL в Docker-томе. Конфигурация с HTTP и демонстрационными настройками базы предназначена для локального запуска.

- `backend/` — Node.js **22.x**, TypeScript, Prisma и PostgreSQL.
- `frontend/` — Node.js **22.x** для сборки, React, TypeScript, Vite и Tailwind CSS.

Проверка API в запущенном Docker:

```sh
docker compose exec backend npm test
```

Проверка ограничения попыток входа через Nginx (только в отдельном тестовом окружении):

```sh
docker compose up -d --force-recreate frontend
docker compose exec -e PROXY_BASE_URL=http://frontend backend npm test
```

Тест намеренно исчерпывает лимит своего IP. Пересоздание тестового frontend перед повторным запуском сбрасывает этот лимит.

Вход и регистрация делят лимит по IP: 5 запросов в минуту с кратковременным запасом в 10 запросов. При превышении Nginx возвращает JSON с HTTP 429 и `Retry-After`. Лимит действует только при доступе через Nginx; при локальной разработке через Vite его нет. За дополнительным reverse proxy потребуется отдельно настроить доверенные адреса, иначе клиенты будут делить IP и лимит прокси.

Задачи хранятся на сервере и доступны после входа, а список загружается при открытии приложения. Синхронизации между вкладками в реальном времени, восстановления пароля и подтверждения email пока нет. Истёкшие сессии пользователя очищаются при его следующем входе; для постоянной эксплуатации нужна отдельная политика очистки. Перед публичным размещением также необходимы HTTPS, Secure-cookie и конфигурация разрешённого origin: текущий сервер принимает браузерные изменения только с localhost/127.0.0.1 на `APP_PORT`.
